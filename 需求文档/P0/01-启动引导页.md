# 启动引导页（用例1）

## 基本流程

1. 用户首次安装后冷启动 APP，进入启动页；
    1. 展示品牌 Logo 与产品口号，停留不超过 1.5 秒；
    2. 同步读取本地「引导页已看」标记与「登录态」标记；
    3. 向后台请求版本信息（`AppUpdateInfo/ver`），判断是否强更。
2. 若「引导页已看」标记不存在，进入引导轮播；
    1. 共 3 屏，横向滑动切换，底部指示点随页切换；
    2. 每屏含插画占位、主标题、副标题；
    3. 第 3 屏显示「立即体验」主按钮，前 2 屏显示「跳过」文字按钮。
3. 点击「立即体验」或「跳过」后写入「引导页已看」标记；
    1. 已登录 → 进入底部导航容器（Tab 首页）；
    2. 未登录 → 进入底部导航容器（Tab 首页，游客态），不强制登录。
4. 已看过引导页的用户直接按第 3 步分流。

## 异常情况

1. 版本接口失败：
    1. 网络异常、超时（3 秒）→ 忽略版本检查，正常进入首页，不阻断启动；
    2. 返回强制更新 → 弹出不可取消弹窗，仅保留「立即更新」按钮，点击跳应用市场；
    3. 返回建议更新 → 弹出可取消弹窗，含「稍后再说」与「立即更新」。
2. 本地存储读取失败：
    1. 视为首次启动，重新展示引导页；
    2. 标记写入失败不阻断跳转，仅记录日志。
3. 图片资源加载失败：
    1. 插画占位显示灰色底块，文案与按钮仍可正常操作。
4. 用户中途杀进程：
    1. 未点击「立即体验」不写入标记，下次启动仍展示引导页。

## 业务规则

1. 引导页仅在「未写入引导标记」时展示，最多展示 1 次；卸载重装视为首次。
2. 引导页不承担登录职责，全程不出现强制登录拦截。
3. 启动页停留时长上限 1.5 秒，版本接口超时 3 秒即放行，不得因网络问题卡住启动。
4. 强制更新弹窗不可关闭、不可返回退出，必须跳转更新。
5. 引导页文案与插画随运营配置下发，本地仅内置兜底 3 屏。
6. 冷启动与热启动均需校验登录态，登录态失效时按游客态进入首页。

## 界面描述

页面为单屏竖版轮播结构：顶部无导航栏（沉浸式），中部为插画区与指示点，底部为主按钮与次级文字入口。第 1、2 屏右上角有「跳过」，第 3 屏无「跳过」、主按钮文案变为「立即体验」。
